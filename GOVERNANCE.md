# Governance

The project is maintainer-led during its initial open-source phase. Maintainers approve
releases, schema and SDK compatibility changes, safety policy, and security responses.
Material decisions should be recorded in pull requests or architecture notes with
alternatives, evidence, migration impact, and dissent.

No single contributor may publish a release artifact without passing the checked
quality gates and protected release workflow. Package publishing and project
renaming require explicit owner approval. Governance may evolve to a multi-maintainer
model after sustained independent contribution.
